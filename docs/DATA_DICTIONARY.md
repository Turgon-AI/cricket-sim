### stg_ari_players

One Cricinfo-derived profile per player known to Ari's dataset.

- **One row is:** One row per player (player_id).
- **Key:** `player_id`
- **Kind:** staging · **Sources:** ari

- **Limitations:** RESTRICTED THIRD-PARTY DATA. This comes from Ari Adaikalam's Kaggle dataset 'The Ultimate Ball-by-Ball Cricket Dataset'. The Cricinfo-derived parts are non-commercial and must credit ESPNcricinfo. It must not be republished or exported; use for analysis and charts only. Profiles are Cricinfo's current snapshot, not as-of the match date: roles, styles and country can differ from what applied years ago, and career-span years leak future information. Styles are static per career. The file covers 9,374 of the 18,651 Cricsheet people (players only, no umpires, and many minor players absent).

### stg_ari_predictions

Commentary-derived predicted line, length, shot and direction, each with a confidence, for 1,654,041 deliveries in 8,563 matches.

- **One row is:** One row per delivery (match_id, innings, delivery_number) with commentary text for which Ari's model produced at least one prediction.
- **Key:** `match_id`, `innings`, `delivery_number`
- **Kind:** staging · **Sources:** ari

- **Limitations:** RESTRICTED THIRD-PARTY DATA. This comes from Ari Adaikalam's Kaggle dataset 'The Ultimate Ball-by-Ball Cricket Dataset'. The Cricinfo-derived parts are non-commercial and must credit ESPNcricinfo. It must not be republished or exported; use for analysis and charts only. The values are model predictions made from Cricinfo commentary text, not observations, and they cannot be checked in-house: the 1.65M rows overlap Cricinfo's recorded labels on only a few thousand balls, and where they do the prediction is empty. Inferred predictions (explicit = false) default heavily to the most common class (good length). A label is present more often for dots than for wickets, so presence depends on the outcome. Use explicit = true labels only, as noisy labels, and keep them separate from recorded labels.

| column | type | description |
|---|---|---|
| `match_id` **key** | VARCHAR | Cricsheet match id (text), the same value as matches.match_id. Part of the key. |
| `innings` **key** | SMALLINT | Innings of the match in the order batted (1 to 6 in this file). Part of the key. |
| `delivery_number` **key** | INTEGER | Position of the delivery within the innings, counting every delivery including wides and no-balls, from 1. Part of the key; matches silver balls.delivery_number. |
| `line` | VARCHAR | Line predicted from the ball's commentary text by Ari's model, always one of Cricinfo's own line labels. NULL where the commentary gives no reading (19,751 rows). |
| `line_confidence` | DOUBLE | Model probability, 0 to 1, that the predicted line equals what Cricinfo would have recorded (assessed by Ari on held-out matches). NULL exactly when line is NULL. (probability 0-1) |
| `line_explicit` | BOOLEAN | True if the commentary text contains words pointing to this line, false if the model inferred it from the wider text and context. NULL exactly when line is NULL. |
| `length` | VARCHAR | Length predicted from the commentary text, always one of Cricinfo's own length labels. NULL where the commentary gives no reading (20,300 rows). |
| `length_confidence` | DOUBLE | Model probability, 0 to 1, that the predicted length equals the Cricinfo label. NULL exactly when length is NULL. (probability 0-1) |
| `length_explicit` | BOOLEAN | True if the commentary words point to this length, false if inferred. 79% of predicted lengths are inferred, and 73% of those are 'good length' (the default class). NULL exactly when length is NULL. |
| `shot` | VARCHAR | Shot name predicted from the commentary text, one of Cricinfo's shot labels. NULL where the commentary gives no reading (82% of rows). |
| `shot_confidence` | DOUBLE | Model probability, 0 to 1, that the predicted shot equals the Cricinfo label. NULL exactly when shot is NULL. (probability 0-1) |
| `shot_explicit` | BOOLEAN | True if the commentary words point to this shot, false if inferred. NULL exactly when shot is NULL. |
| `direction` | VARCHAR | Shot direction predicted from the commentary text, one of Cricinfo's eight direction names. NULL where the commentary gives no reading (83% of rows). |
| `direction_confidence` | DOUBLE | Model probability, 0 to 1, that the predicted direction equals the Cricinfo label. NULL exactly when direction is NULL. (probability 0-1) |
| `direction_explicit` | BOOLEAN | True if the commentary words point to this direction, false if inferred. NULL exactly when direction is NULL. |

### stg_ari_tracking

Cricinfo ball-tracking attributes for 4,468,782 deliveries in 9,510 matches, taken from Ari's cricinfo_tracking.csv with columns renamed to snake_case and typed.

- **One row is:** One row per delivery (match_id, innings, delivery_number) that Ari's file has a tracking record for.
- **Key:** `match_id`, `innings`, `delivery_number`
- **Kind:** staging · **Sources:** ari

- **Limitations:** RESTRICTED THIRD-PARTY DATA. This comes from Ari Adaikalam's Kaggle dataset 'The Ultimate Ball-by-Ball Cricket Dataset'. The Cricinfo-derived parts are non-commercial and must credit ESPNcricinfo. It must not be republished or exported; use for analysis and charts only. Cricinfo's line, length, shot and control labels are observer labels recorded after the outcome of the ball is known, so they depend on what happened (shot control almost encodes the wicket: 13.7% of 'not in control' balls are wickets against 0.36% otherwise), and must not feed a decision model. Coverage is uneven: line and length are missing for 38% of rows and are absent for Tests and ODIs before 2014; ball timestamps only start in Oct 2019; win probability and projected score exist on about 23% of rows. Source keys are built from Cricsheet, so every row joining to silver balls is expected by construction. Staging does no cleaning: empty strings and blanks become NULL and nothing else is changed.

| column | type | description |
|---|---|---|
| `match_id` **key** | VARCHAR | Cricsheet match id (text), the same value as matches.match_id. Part of the key. All 9,510 matches here exist in silver matches. |
| `innings` **key** | SMALLINT | Innings of the match in the order batted, numbered as in silver balls.innings (1 to 4 in this file). Part of the key. |
| `delivery_number` **key** | INTEGER | Position of the delivery within the innings, counting every delivery including wides and no-balls, starting at 1. Part of the key; identical in meaning to silver balls.delivery_number, and every row here has a matching silver ball. |
| `ball_line` | VARCHAR | Cricinfo's label for the line of the ball: 'outside offstump', 'wide outside offstump', 'on the stumps', 'down leg' or 'wide down leg'. NULL when Cricinfo has no value (about 38% of rows; Tests and ODIs before 2014 have none). Relative to the batter, not the ground. Observer label recorded after the outcome. |
| `ball_length` | VARCHAR | Cricinfo's label for the length of the ball: 'full toss', 'yorker', 'full', 'good length', 'short of a good length' or 'short'. NULL when Cricinfo has no value (about 38% of rows). Observer label recorded after the outcome. |
| `shot_played` | VARCHAR | Cricinfo's name for the shot, for example 'cover drive', 'flick', 'defended', 'left alone', 'no shot'. Free vocabulary of about 40 names; names used before 2014 are coarser (for example 'forward defence', 'off side drive on front foot'), so the same shot can have two names across eras. NULL when not recorded. Observer label recorded after the outcome. |
| `shot_control` | VARCHAR | Whether Cricinfo judged the batter to be in control of the shot: 'in control' or 'not in control'. NULL when not recorded (3.4% of rows). Nearly encodes whether a wicket fell, so it is a result-class label, not a pre-ball feature. |
| `wagon_x` | INTEGER | Horizontal pixel coordinate of where the ball went on Cricinfo's wagon-wheel graphic (observed 0 to 364). NULL when no wagon-wheel point exists (22.6% of rows, e.g. dots and wickets); NULL together with the other wagon_* columns. (pixels) |
| `wagon_y` | INTEGER | Vertical pixel coordinate on Cricinfo's wagon-wheel graphic (observed 0 to 381). NULL exactly when wagon_x is NULL. (pixels) |
| `wagon_zone` | SMALLINT | Wagon-wheel sector, 1 to 8, as Cricinfo numbers it. Zones are not tied to a fixed side of the ground: the same shot_direction can appear under two zone numbers (cover occurs in zones 3 and 6). NULL when wagon_x is NULL. |
| `wagon_angle` | DOUBLE | Direction of the shot in degrees from 0 to just under 360, with 0 straight behind the batter. Left-handers are mirrored so the angle is relative to the batter's off side. NULL when wagon_x is NULL. (degrees) |
| `wagon_distance` | DOUBLE | How far the ball travelled as a fraction of the way from the centre of the field to the boundary; can exceed 1 (observed up to 1.39). NULL when wagon_x is NULL. (fraction of boundary distance) |
| `wagon_in_ring` | BOOLEAN | True if the shot ended inside the 30-yard fielding circle, false if outside. NULL when wagon_x is NULL. |
| `shot_direction` | VARCHAR | The wagon-wheel zone as a name: fine leg, square leg, mid wicket, mid on, mid off, cover, point or third man. Left-handers are mirrored, so 'cover' is always the off side. NULL when wagon_x is NULL. |
| `ball_timestamp` | TIMESTAMP | Cricinfo's record time of the delivery, in UTC (no time-zone marker in the column). Only exists from 30 Oct 2019 (about 41% of rows); NULL otherwise. It is the time Cricinfo logged the ball, not a verified bowling time. |
| `win_probability` | DOUBLE | Cricinfo's estimated chance, in percent (0 to 100), that the batting side wins at this ball, in both innings. NULL on about 77% of rows. It was computed after the fact by a Cricinfo model, so it is a benchmark, not a pre-ball input. (%) |
| `predicted_score` | INTEGER | Cricinfo's projected final innings score at this ball, in runs. NULL exactly when win_probability is NULL. (runs) |
| `ball_events` | VARCHAR | Events Cricinfo logged on the ball, as lowercase phrases separated by '; ' (for example 'drs review (unsuccessful)', 'dropped catch', 'bowler change', 'end change', 'run out chance', 'player replacement'). NULL on 99% of rows. A 'bowler change' is usually attached to the last ball of the previous over rather than the new bowler's first ball, so it leaks the next decision into the current ball. |

### stg_hawkeye_balls

Hawk-Eye tracking record per delivery from the ICC feed, 1,115,694 rows over 628 IPL, 822 ODI and 317 Test matches.

- **One row is:** One row per delivery in a Hawk-Eye match (competition, hawkeye_match_id, delivery_code).
- **Key:** `competition`, `hawkeye_match_id`, `delivery_code`
- **Kind:** staging · **Sources:** hawkeye

- **Limitations:** RESTRICTED THIRD-PARTY DATA. The source repository alittlefitness/HawkeyeStats states no licence, so all rights are reserved: it must not be republished or exported; analysis and charts only. Coverage is limited to 2011-2021 IPL, ODI and Test matches (1,767 matches; no T20Is, no women's cricket, nothing after Nov 2021), and Hawk-Eye was present on a selected set of big series and well-televised hosts, so it is not representative. It also does not track every ball (pitch coordinates missing on 27% of rows, speed on 29.5%). Staging keeps the source's sentinels and junk values (-1 speeds, 0/(5,5) field points, 1e18-sized coordinates) untouched; silver nulls them. 'NA' bowling style stays as text.

### balls

One row per delivery bowled, including wides and no-balls, with participants (names and Cricsheet person ids), runs, extras breakdown, wicket and review flags.

- **One row is:** One row per delivery (match_id, innings, delivery_number).
- **Key:** `match_id`, `innings`, `delivery_number`
- **Kind:** event · **Sources:** cricsheet

- **Limitations:** Cricsheet (ODC-BY 1.0); format documented at https://cricsheet.org/format/json/. Contains 11.7M deliveries from all 23,132 matches (no scope filter). Positions follow Cricsheet, so over is 0-based, ball_in_over includes wides/no-balls, and a few hundred overs have other than six legal balls (290 listed as miscounted by Cricsheet; one 7-ball over in match 1298152 is not listed). Pre-late-2017 no-balls have byes folded into the noballs count, which overstates bowler runs conceded in that era. wicket_count includes retirements, so do not use wicket_count > 0 as 'dismissal'. Fielding positions, field settings and ball tracking are NOT here; they come from third-party layers. Afghanistan matches are missing from Cricsheet.

| column | type | description |
|---|---|---|
| `match_id` **key** | VARCHAR | Cricsheet match id; foreign key to matches. Part of the key. |
| `innings` **key** | SMALLINT | Innings of the match in batting order (1 to 8; 3+ includes Test third/fourth innings and super overs). Part of the key. |
| `batting_team` | VARCHAR | Team batting in this innings (innings.team). |
| `is_super_over` | BOOLEAN | True if the delivery belongs to a super-over innings. |
| `delivery_number` **key** | INTEGER | Running count of every delivery in the innings, wides and no-balls included, from 1. Part of the key. This is Ari Adaikalam's convention, so Ari tracking and Hawk-Eye link on it. |
| `over` | SMALLINT | Over number, 0-based as in Cricsheet (the first over is 0). Add 1 for the usual 'over 1'. (over (0-based)) |
| `ball_in_over` | SMALLINT | Position of the delivery within the over counting every delivery incl. wides and no-balls (1 to 21). It is NOT the legal ball number: use actual_delivery or legal_balls_in_over_before for that. Overs with more or fewer than 6 legal balls (miscounted overs) are listed in innings.miscounted_overs. |
| `is_legal` | BOOLEAN | False for wides and no-balls (the delivery does not count toward the over), true otherwise. |
| `batter` | VARCHAR | Name of the striker (Cricsheet name, initials+surname). |
| `batter_id` | VARCHAR | Cricsheet person identifier of the striker; foreign key to people.identifier. Never NULL. |
| `non_striker` | VARCHAR | Name of the non-striker. |
| `non_striker_id` | VARCHAR | Cricsheet person identifier of the non-striker; foreign key to people.identifier. |
| `bowler` | VARCHAR | Name of the bowler. |
| `bowler_id` | VARCHAR | Cricsheet person identifier of the bowler; foreign key to people.identifier. |
| `runs_batter` | SMALLINT | Runs scored off the bat on this delivery (0 to 8), including boundaries. Byes and leg-byes are not included. (runs) |
| `runs_extras` | SMALLINT | Extra runs on this delivery: wides + no-balls + byes + leg-byes + penalty. (runs) |

### cricinfo_ball_labels

- **One row is:** One row per ball (match_id, innings, delivery_number) with at least one non-NULL label, 4,399,294 rows over 9,214 matches.
- **Key:** `match_id`, `innings`, `delivery_number`

### hawkeye_match_link

Link between each Hawk-Eye match and the Cricsheet match it describes, with a confidence and an agreement measure; unmatched Hawk-Eye matches are kept with a NULL match_id.

- **One row is:** One row per Hawk-Eye match (hawkeye_match_id within competition), 1,767 rows.
- **Key:** `competition`, `hawkeye_match_id`
- **Kind:** event · **Sources:** hawkeye, cricsheet, derived · **Built from:** `stg_hawkeye_balls`, `balls`, `matches`, `people`

- **Limitations:** Covers only men's Test, ODI and IPL matches in the HawkeyeStats feed (frozen February 2022). 78 of 1,767 Hawk-Eye matches are unmatched (76 ODI, 2 Test; no IPL): most are Afghanistan matches, which Cricsheet withholds. A Hawk-Eye match counts as linked only if at least half of its balls agree with a Cricsheet match on runs, batter and bowler, and each Cricsheet match is used by at most one Hawk-Eye match. ### match_weather_hourly

Hourly weather values around a format-default time window for each match day, covering the 12 hours before the estimated start and the estimated playing window.

- **One row is:** One row per match, match day and UTC hour (match_id, match_day_number, utc_datetime), 246,234 rows over 11,550 match-days.
- **Key:** `match_id`, `match_day_number`, `utc_datetime`
- **Kind:** event · **Sources:** weather, cricsheet, derived · **Built from:** `matches`, `venues`

- **Limitations:** Weather is modelled reanalysis (ERA5 via Open-Meteo, CC BY 4.0, free API for non-commercial use) for the venue's point, not a station measurement; where the point is a city centre or unverified (see venues.weather_location_quality) it can differ from the ground. Only match days with weather are present: 8,520 of 23,132 matches (11,550 match-days), because 273 venues are not located and venues outside the weather plan have no data, and match days too new for the weather archive would be missing (none in the current build). The window is a fixed format default for every match day; exact play timestamps are used only in internal summaries. It does not know about day/night matches, rain delays or actual play, and ERA5 missed the evening rain that stopped the 2019 World Cup semi-final, so it is not rain truth. The key includes utc_datetime because a Test day's play window can cross midnight into the next day's window.

### dim_match

### dim_player

Every player who appears in an in-scope match: Cricsheet and ESPNcricinfo identifiers, linked Wikidata item, date of birth with quality flag, birthplace, sex, nationality and how it was decided, citizenships, and match counts and first/last dates overall and per segment.

- **One row is:** One row per player (Cricsheet person) who appears on a team sheet of at least one in-scope match.
- **Key:** `cricsheet_id`
- **Kind:** dim · **Sources:** wikidata_players, cricsheet, derived · **Built from:** `players`, `match_players`, `matches`

- **Limitations:** Birth data comes from Wikidata, linked by ESPNcricinfo id, and is only as good as Wikidata: dob is NULL for about 10% of players, and conflicting, placeholder or implausible dates are nulled with a reason in dob_flag. Handedness is almost never recorded in Wikidata (10 players) and height is not published. country is the national team the player actually played for, not citizenship. Career counts and first/last dates are whole-career figures as of the data snapshot, computed over all Cricsheet matches; they look into the future relative to any given match, so do not use them as model features (recompute as of each match date). Career spans and totals are deliberately not here: they summarise the whole snapshot and would leak the future into a model. ### dim_venue

- **One row is:** One row per canonical venue (ground) referenced by dim_match.
- **Key:** `venue_id`

- **Limitations:** Coordinates come from Wikidata, pinned OpenStreetMap elements, OSM Nominatim or manual overrides, in that order of preference, and are a point for the ground, not its outline. 7 venues are located only to the city centre (geocode_source 'nominatim_city', weather_location_quality 'city_centroid') and 11 are flagged needs_review. ### fact_delivery

Every delivery of every in-scope match, with the batting side, over and ball position, the players on the field, the pre-ball match state (score, wickets, balls left, target, runs required, Test lead) and the ball's outcome (legality, runs by type, boundaries, extras, wickets, DRS review).

- **One row is:** One row per delivery bowled (wides and no-balls included), keyed by (match_id, innings, delivery_number).
- **Key:** `match_id`, `innings`, `delivery_number`
- **Kind:** fact · **Sources:** cricsheet, derived · **Built from:** `balls`, `matches`, `int_ball_state_pre`

- **Limitations:** Scope: men's Tests, ODIs, T20Is between two ICC full members, and the IPL, from 2001 (config/scope.yml); Cricsheet coverage is incomplete (see report_international_coverage; e.g. Afghanistan matches are withheld by Cricsheet). The '_before' columns never include the ball itself; the build checks that the next ball's state equals this state plus this ball. ### model_ball_outcome

For every ODI delivery modelled: the probability of each of eight outcomes and the expected runs, from a gradient-boosted classifier trained walk-forward on the ten seasons before the match.

- **One row is:** One row per delivery of innings 1 and 2 of an ODI from 2008 onwards.
- **Key:** `match_id`, `innings`, `delivery_number`
- **Kind:** model · **Sources:** cricsheet, derived · **Built from:** `fact_delivery`, `fact_innings`, `dim_match`

- **Limitations:** Describes an average batter facing an average bowler in that match state and season: it knows nothing about the actual players, pitch or conditions, by design. Outcome classes use total runs off the delivery (a five is counted with fours, sevens with sixes). Extras = wides and no-balls. Numeric outputs are NULL for excluded matches, including unknown target/horizon event times; evaluated and exclusion_reason explain eligibility.

| column | type | description |
|---|---|---|
| `match_id` **key** | VARCHAR | Cricsheet match id (joins gold.fact_delivery and gold.dim_match). |
| `innings` **key** | SMALLINT | Innings number: 1 = batting first, 2 = chasing. Super overs are not modelled. |
| `delivery_number` **key** | INTEGER | Delivery sequence within the innings, wides and no-balls included (as in gold.fact_delivery). |
| `trained_through_season` | BIGINT | Last season the model that produced this row was trained on. It is always earlier than the match's season: every prediction is out of sample. |
| `p_dot` | DOUBLE | Probability that this delivery ends as 'dot': a legal ball with no runs and no wicket. (probability) |
| `p_1` | DOUBLE | Probability that this delivery ends as '1': one run. (probability) |
| `p_2` | DOUBLE | Probability that this delivery ends as '2': two runs. (probability) |
| `p_3` | DOUBLE | Probability that this delivery ends as '3': three runs. (probability) |
| `p_4` | DOUBLE | Probability that this delivery ends as '4': four (or five) runs. (probability) |
| `p_6` | DOUBLE | Probability that this delivery ends as '6': six or more runs. (probability) |
| `p_wicket` | DOUBLE | Probability that this delivery ends as 'wicket': a dismissal on this delivery, including run-outs. (probability) |
| `p_extra` | DOUBLE | Probability that this delivery ends as 'extra': a wide or no-ball without a wicket. (probability) |
| `expected_runs` | DOUBLE | Expected total runs off this delivery: the outcome probabilities times the average runs of each outcome in the training seasons. (runs) |
| `evaluated` required | BOOLEAN | True when the match meets the same training and scoring eligibility rules as the win-probability table. |
| `exclusion_reason` | VARCHAR | Reason numeric outputs are withheld; NULL on evaluated rows. Same value as model_ball_win_probability. |

### model_ball_win_probability

For every delivery of the first two innings of an in-scope ODI: the batting side's probability of winning before the ball, after it, and the swing (win probability added), when the match is evaluable. Produced walk-forward (src/cricket_sim/models). See docs/MODEL_CARD.md.

- **One row is:** One row per delivery of innings 1 and 2 of an ODI in a season the model could be trained for (2008 onwards).
- **Key:** `match_id`, `innings`, `delivery_number`
- **Kind:** model · **Sources:** cricsheet, derived · **Built from:** `fact_delivery`, `fact_innings`, `dim_match`, `dim_venue`

- **Limitations:** A tie counts as half a win. Super overs are not modelled. Rows for matches excluded from evaluation are retained with evaluated = false and a reason, but numeric win-probability and expected-runs outputs are NULL: Cricsheet does not identify when revised targets or shortened innings became known. Inputs are the match state, pre-match Elo and an as-of venue-home estimate only: no team selection, pitch, weather or player information.

| column | type | description |
|---|---|---|
| `match_id` **key** | VARCHAR | Cricsheet match id (joins gold.fact_delivery and gold.dim_match). |
| `innings` **key** | SMALLINT | Innings number: 1 = batting first, 2 = chasing. Super overs are not modelled. |
| `delivery_number` **key** | INTEGER | Delivery sequence within the innings, wides and no-balls included (as in gold.fact_delivery). |
| `batting_team` | VARCHAR | Team batting on this ball (the side whose win probability is given). |
| `trained_through_season` | BIGINT | Last season the model that produced this row was trained on. It is always earlier than the match's season: every prediction is out of sample. |
| `wp_before` | DOUBLE | Probability that the batting side wins, given everything known before this ball on evaluated rows; NULL otherwise: the match state (through a learned resources table and smooth spline terms for balls left, wickets down and, when chasing, the required rate), the pre-match Elo difference and home advantage. Monotone by construction: in innings 1 it never falls as runs rise, it never rises with a wicket down, and in a chase it never rises as more runs are needed (at least 0.5 once scores are level). (probability) |
| `wp_after` | DOUBLE | The batting side's win probability after this ball: the next ball's wp_before within an innings; after the last ball of innings 1, the innings-1 model's value for the state after that ball (so the gap between the innings-1 and chase models at the innings break is credited to no ball, and wpa does not sum across the break); or the actual result after the match's last ball (1 win, 0 loss, 0.5 tie), on evaluated rows only. NULL otherwise. (probability) |
| `wpa` | DOUBLE | Win probability added by this ball for the batting side: wp_after - wp_before. Positive helps the batting side. NULL when the match is not evaluated. (probability) |
| `expected_remaining_runs` | DOUBLE | Expected runs still to come in this innings for an average side, given legal balls left and wickets down (a DLS/WASP-style resources table re-learned each season from earlier first innings); NULL when not evaluated. (runs) |
| `evaluated` | BOOLEAN | True when the match is clean (no rain rule, a result, both innings of known length, unrevised chase, passes quality) and so counts in report_model_scores. |
| `exclusion_reason` | VARCHAR | Why a match is not evaluated: no_result, rain_rule_applied, fails_quality_checks, innings_length_unknown or chase_target_not_set. NULL when evaluated. |

### report_model_paired

- **Kind:** report · **Sources:** cricsheet, derived · **Built from:** `model_ball_win_probability`, `model_ball_outcome`

- **Limitations:** Clean held-out balls only. The sign test treats seasons as exchangeable and ignores their size. The baselines do not all get the same inputs as the model (the state logistic has no home term).
